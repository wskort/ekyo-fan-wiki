Bestaat uit 3 [[API]]'s, 1 [[Database]] en 1 background process (file slurper). 
- [[PI Management API]] ([swagger](https://isv-web-t01/payment-instrument-management-pre/development/swagger/index.html)) (nog niet in gebruik)
	- Bedoeld om te gaan koppelen met [[Connect]] en dan daarin te kunnen aanpassen
	- Create or update Program Manager (en ook aanmelden bij Enfuce als 'corporate customer'). 
	- accessControlList bepaalt obv merchantId, merchantCategoryCode of merchantCategoryGroup (evt + merchantCountryCode) of iets whitelisted of blacklisted is.  
	- PaymentRequests kan data opvragen obv auth.trans. in Intersolve logs, dus levert de bijbehorende Enfuce/Visa data. Voor ons telt de merchant als 'Enfuce' maar die weten dus wat de daadwerkelijke partij was. (OperationReference)
- [[PI Payment API]] ([swagger](https://isv-web-t01/payment-instrument-payment-pre/development/swagger/index.html)) ()
	- Aanmaken & koppelen nieuwe kaart
	- CVC code en expiry date opvragen via rendered URL die in iFrame getoond wordt, maar dus niet door machines gelezen kan worden. 
	- Pin-code mocht niet via post, dus ook via rendered URL die in iFrame getoond wordt, maar dus niet door machines gelezen kan worden. 
	- Wel gebouwd, niet geïmplementeerd: provisioning apple-pay/google-pay om de virtuele kaart in een digi wallet te kunnen steken. 
- [[PI Processing API]] ([swagger](https://isv-web-t01/payment-instrument-processing-pre/development/swagger/index.html)) legt via [[Enfuce]] (externe partij) contact met [[Visa]] (clear = akkoord, gaat in productie niet via API maar via file)
	- Payment Authorization Request vanuit [[Enfuce]]
		- Check dat data overeenkomt met onze data (Enfuce's accountId, customerId, etc.)
		- AccessControlList checken. 
		- linkId (unique ID van transaction) is nieuw
		- transactionAmount > amount in currency van transactie
		- settlementAmount > amount in target currency
		- transactionType vergelijken met lijst in config van [[PI Processing API]]. 
	- Atm: 1 fysiek & 1 digitaal token per klant. !! Dus ook alleen moeilijk omwerken bij verloren kaart. Bestaande token afsluiten, leegtrekken, nieuwe kaart maken met nieuwe customer en daarop storten. 
	- Bedrag wordt voor X tijd op 'Reserved' gezet. (Voor [[Rode Kruis]] 7 dagen)
	- Notifications for data updates from [[Enfuce]]. E.g. foute pin event. 
		- `91`: Timeout van onze verwerking, namens [[Enfuce]].
			- Dus niet verwerkt door hen, dus enige verwerking van onze kant terugdraaien!! (Cancellen op [[POS-API]])
			- Als al gemeld als 'laat maar', indien transactie überhaupt pas later binnenkomt ook niet uitvoeren. 
- [[PI Database]] 
	- Koppeltabel tokens & enfuce codes
	- Regels rondom toestaan transacties
- [[PI Worker]] (Clearing Feeder) (Capture request in [[POS-API]]) is de background process die [[JSON]] statement files leest en per regel een geauthoriseerde transactie valideert. 
	- Mislukte payments gaan naar [[Disputed Payments]]: handmatig bestand waarmee wij terug stappen naar [[Enfuce]].
